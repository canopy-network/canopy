# Fee Structure

:::tip In one sentence
canoLiq keeps 12% of the staking rewards it earns and passes the other 88% straight to cCNPY
holders — and because 40% of that fee is rebated, holders end up with 92.8% of every reward.
:::

canoLiq applies a **12% protocol fee** (`fee_bps = 1200`) on staking rewards. The rest of the
reward — the other 88% — lifts the exchange rate for everyone. The fee itself is split across
four destinations.

## Fee Split (40/30/15/15)

| Destination | BPS | Percentage | In plain terms |
|-------------|-----|------------|----------------|
| User Rebate | 4000 | 40% | Goes straight back into the pool, raising the cCNPY exchange rate for all holders |
| DAO Treasury | 3000 | 30% | Funds the protocol's operations, grants, and the insurance reserve |
| Validators | 1500 | 15% | Pays the committee validators securing the chain, pro-rata to stake |
| Buyback | 1500 | 15% | Saved to buy back CPLQ later |

The four split fields must always sum to `10,000` bps (100% of the fee).

Because the user rebate flows back into the pool, cCNPY holders receive **92.8%** of every
reward canoLiq takes in (88% directly, plus 4.8% via the rebate) — not 88%.

## Insurance Auto-Routing

A small fraction of the **treasury slice** is skimmed into an insurance reserve:

- **`insurance_bps`**: default **500 (5% of the treasury slice ≈ 1.5% of the total fee)**
- The skim **turns off automatically** once the reserve reaches its target (a fraction of
  peak TVL), and resumes as the protocol grows. See [Insurance Fund](../advanced/insurance.mdx)
  for the full mechanism.

## Reference Values

For a 1000 uCNPY reward with the 12% fee and default split (insurance skim active):

| Component | Amount (uCNPY) |
|-----------|----------------|
| Post-DAO (5% cut applied upstream) | 950 |
| Fee (12% of 950) | 114 |
| User Rebate (40%) | 45 |
| Treasury (30%, after the insurance skim) | 34 |
| Insurance (5% of the treasury slice) | 1 |
| Validators (15%) | 17 |
| Buyback (15%) | 17 |
| **Sum** | **114** |

## Fee Conservation

The components always add back to the fee exactly:

```
userRebate + treasury + insurance + validators + buyback = feeAmount
```

Integer division truncates each slice, so the few uCNPY left over are folded into the treasury.
When the insurance skim is off, the would-be insurance amount stays in the treasury — the
equation still balances.

:::note
The 5% DAO cut is applied **upstream** by Canopy core, before rewards ever reach the canoLiq
committee pool. The plugin sees only `0.95 × X`. Do not double-apply the DAO cut inside the
plugin.
:::
